# STM32 serial bridge

Current firmware: USART2 PA2 TX / PA3 RX, 115200 8N1. Command v1: 13 bytes;
telemetry v3: 52 bytes. Multi-byte fields little endian; CRC-16/CCITT-FALSE.
MPU6050: +/-2g, +/-2000 deg/s. Temperature is Celsius.

Build with colcon in ~/work/curiousrobot. Start:
```bash
ros2 launch stm32_base_bridge bridge.launch.py port:=/dev/serial/by-id/YOUR_ADAPTER
```
Topics: subscribes /cmd_vel (geometry_msgs/Twist); publishes /odom/unfiltered,
 /imu/data (raw angular velocity and acceleration, no orientation), /imu/temperature,
 /diagnostics. Invalid sensor fields are not published. No odometry TF is sent.
The EKF owns odom -> base_footprint.

Heartbeat 20 Hz; upstream cmd_vel timeout 0.2 s measured with monotonic time.
Repeated heartbeats never refresh the upstream timeout. On startup/reconnect,
stale telemetry, invalid command, or motor write fault: discard old velocity.
A new command after healthy telemetry is required to move again. Firmware's
independent timeout is 300 ms; loss of power/bus may prevent a stop write.
Short serial writes are treated as failures. On orderly exit, send zero once.
No physical motion is generated by running the node alone.
Only linear.x and angular.z are supported. Non-finite or unsupported components
clear the command. Supported velocities are clamped to configured limits;
STM32 performs wheel-speed scaling. No per-frame ACK exists in this protocol.

ROS message stamps use host reception time, not MCU millis. MCU reboot clears
pending motion; it also resets the MCU's raw odometry origin. EKF fuses twist only.
Missing sensor data causes diagnostics errors, not fabricated zero measurements.
Covariances are configurable starting estimates and need real calibration.
With a stationary IMU, verify bias and axis directions before relying on fusion.
Parameters are startup-only; restart the node after editing bridge.yaml.

Offline simulator:
```bash
ros2 run stm32_base_bridge mock_mcu --link /tmp/curiousrobot_test_serial
ros2 launch stm32_base_bridge bridge.launch.py port:=/tmp/curiousrobot_test_serial
```
Use a fresh link path; simulator refuses to replace existing files.
The simulator is only for interface tests, not a physical dynamics model.
Run unit tests with colcon test --packages-select stm32_base_bridge.
